## Goal
Unblock `make up` / `make all` on dev machines and move ASR/Vosk to Docker-managed flow without local model dependency.

## What Was Done
- Switched ASR runtime wiring to Docker Vosk websocket (`VOSK_SERVER_URL`) instead of local `VOSK_MODEL_PATH`.
- Added `vosk` service (`alphacep/kaldi-en`) to `docker-compose.yml`.
- Updated Make targets so Vosk is part of normal stack flow.
- Added `pull-images` target and wired it into `bootstrap`.
- Fixed `verify-vosk-api` to fail correctly if ASR payload is missing.
- Added `.dockerignore` to keep Docker build context small.

## Critical Build Issues Found
1. `ort-sys` failed on Alpine/musl (`x86_64-unknown-linux-musl`) because prebuilt ONNX Runtime is not provided there.
2. After moving to glibc image, linking still failed with `__isoc23_strtol`/`__isoc23_strtoll` symbols from ORT binaries.

## Mitigation Applied (Historical Dev-first)
Initial unblock work used a conservative fallback path and a debug-profile Docker build to keep local API development moving.
Current runtime has moved forward from that temporary state; see **Current Known Behavior** below for the effective behavior.

## Current Known Behavior
- Docker Vosk image is used (`alphacep/kaldi-en`).
- Dev Docker builds are not optimized.
- Silero VAD is active when API is built with `vad_silero` (now directly mapped to `app_core/vad_silero`).
- In strict mode, unsupported provider names and missing required provider config fail fast.
- Stable Docker verification path uses `api_vosk` with `asr_vosk` + `energy` VAD.
- `api_vosk_silero` remains available for explicit Silero runtime checks, but may hit ORT/glibc linker issues depending on host toolchain/runtime.

## Next Steps For New Codex Instance
1. Run:
   - `make up`
   - `make keycloak-setup`
   - `make verify-stack`
   - `make verify-vosk-api`
2. If ASR payload still missing, inspect:
   - `docker compose logs --tail=200 api`
   - `docker compose logs --tail=200 vosk`
3. Keep runtime profiles consistent:
   - default compose API profile uses `ASR_PROVIDER=vosk_remote` and `VAD_PROVIDER=energy`;
   - keep strict mode enabled in demo/prod-like profiles;
   - use `verify-vosk-api` as required acceptance check; `verify-vosk-silero-api` as optional best-effort check.
